# CS300Projects

PROBLEM

  ABC University has commissioned for software to help their computer science advisors access course information for their students. ABCU tasked me with creating pseudocode to import the class structure data for sorting and storing for retrieval. ABCU wanted to explore different data structures to determine the best option for their software application. For these projects, I evaluated the strengths, trade-offs, and differences between vectors, hash tables and binary search trees in order to make an informed decision on the best data structure for ABCU's requirements. 

APPROACH

  I approached this problem by first analyzing the requirements provided by ABC University and identifying the primary operations the software would need to perform. Since course information needed to be imported, stored, sorted, and retrieved efficiently, selecting the appropriate data structure became the central design decision. Understanding data structures is important because they directly impact how efficiently data can be stored, searched, and maintained. By evaluating vectors, hash tables, and binary search trees, I was able to compare the strengths and tradeoffs of each structure and determine which option best aligned with the needs of the project.

CHALLENGES

  One of the biggest challenges was understanding the practical differences between the data structures beyond their textbook definitions. While it is easy to learn how a vector, hash table, or binary search tree works individually, it was more difficult to understand when one should be used over another. I overcame this challenge by comparing their performance characteristics, considering how each structure handled searching and sorting operations, and testing how they would perform within the context of the course scheduling application. This allowed me to make decisions based on application requirements rather than assumptions.

  Another thing to note: I also struggled considerably in the use of a Big O analysis. This concept is completely new to me, and I feel that I needed more time studying this in order to perform the analysis more effectively. I think with more time and experience, I could perform a Big O anaylsis for a future employer with greater precision.

LEARNING CURVE

  This project reminded me of the importance of using the appropriate data structures in the early software design considerations. Before this course, I focused primarily on code execution and design practices within the coding environment. Beyond designing pseudocode or flowcharts/UML diagrams, I did not take quite as much consideration of the infrastructure of coding design and how that could affect runtime and outcomes. Evaluating multiple possible solutions before implementation helped me to better understand how design decisions can drastically affect the application's usability, performance, and reusability. 

REFLECTION 

  This project encouraged me to think more carefully about program organization and long-term maintainability. Rather than focusing only on immediate functionality, I learned to consider how future modifications might affect the software. Writing modular code, using descriptive naming conventions, separating functionality into logical components, and selecting appropriate data structures all contribute to making programs easier to read, maintain, and expand. These are practices I plan to continue using in future software development projects.
